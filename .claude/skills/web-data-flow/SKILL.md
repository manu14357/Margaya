# Web data flow

Purpose: take one API route all the way to a correct, live-updating UI in `apps/web`, the way the existing features do it. Root rules: [AGENTS.md](../../../AGENTS.md). Related skills: `api-endpoint` (the route itself), `realtime-events` (event to WebSocket path), `permissions`, `i18n`, `testing`.

Worked example to copy from (every layer exists): **trash**.

| Layer | File |
| --- | --- |
| API routes (operationIds) | `apps/api/src/trash/index.ts` |
| Fetchers | `apps/web/src/fetchers/trash/task-trash.ts` |
| Query keys | `apps/web/src/hooks/queries/trash/trash-query-keys.ts` |
| Query hook | `apps/web/src/hooks/queries/trash/use-task-trash.ts` |
| Mutation hooks | `apps/web/src/hooks/mutations/trash/use-trash-mutations.ts` |
| Component with states | `apps/web/src/components/trash/trash-list.tsx`, `task-trash-view.tsx` |
| Route | `apps/web/src/routes/_layout/_authenticated/dashboard/settings/projects/$projectId/trash.tsx` |
| Realtime | `TRASH_HINTS` in `apps/web/src/hooks/use-project-websocket.ts` |
| Component test | `apps/web/src/components/trash/trash-views.test.tsx` |

Smaller example for single-call fetchers: `apps/web/src/fetchers/label/*.ts` with `hooks/queries/label/` and `hooks/mutations/label/`.

## Steps

1. **Confirm the API route exists and is typed.** The client type is `AppType` in `apps/api/src/index.ts`, consumed by `packages/libs/src/hono.ts`. A new feature router (built with `apiRouter()` from `apps/api/src/openapi.ts`) must be mounted there with `api.route("/<path>", router)` and its `typeof` added to the `AppType` union (see `trashApi`), or `client.<path>` will not type-check. API changes also need `docs-and-openapi`.

2. **Write the fetcher** in `apps/web/src/fetchers/<feature>/<verb-noun>.ts`. One request per function, no React. Pattern (from `fetchers/label/update-label.ts`):
   ```ts
   import { client } from "@margaya/libs";
   import type { InferRequestType } from "hono/client";
   import { HttpError } from "@/lib/http-error";

   export type UpdateLabelRequest = InferRequestType<
     (typeof client)["label"][":id"]["$put"]
   >["json"] & InferRequestType<(typeof client)["label"][":id"]["$put"]>["param"];

   async function updateLabel({ id, name, color }: UpdateLabelRequest) {
     const response = await client.label[":id"].$put({ param: { id }, json: { name, color } });
     if (!response.ok) throw new HttpError(response.status, await response.text());
     return response.json();
   }
   export default updateLabel;
   ```
   Always throw `HttpError` on `!response.ok`: the global cache handler in `apps/web/src/query-client/index.ts` uses it for 401 handling. Never call `fetch` directly for API routes.

3. **Define query keys.** For anything with more than one query, add a `<feature>-query-keys.ts` factory whose keys share a prefix, so one invalidation refreshes all of them. Copy `hooks/queries/trash/trash-query-keys.ts` or `hooks/queries/cycle/cycle-query-keys.ts`. Before inventing a key, grep for existing ones (`grep -rn 'queryKey: \["labels"' apps/web/src`): other hooks and the websocket handler already invalidate those prefixes.

4. **Write the query hook** in `hooks/queries/<feature>/use-*.ts`: `useQuery` (or `useInfiniteQuery` for paged lists, as `use-task-trash.ts` does) with `enabled: Boolean(id)` when an id can be empty.

5. **Write the mutation hook** in `hooks/mutations/<feature>/`. Decide what the change makes stale and invalidate exactly that, in `onSuccess` or `onSettled`. Examples:
   - Invalidate-only: `hooks/mutations/label/use-update-label.ts`.
   - Write the result into the cache, then invalidate: `hooks/mutations/label/use-create-label.ts`.
   - Shared refresh helper for several mutations: `refreshAfterTaskChange` in `hooks/mutations/trash/use-trash-mutations.ts`.
   - Task lists and views: call `invalidateTaskQueries(queryClient, projectId)` from `@/lib/task-query/cache`.
   - Optimistic update: `hooks/mutations/favorite/use-toggle-favorite.ts` (`onMutate` cancels and snapshots, `onError` restores the snapshot, `onSettled` invalidates). Use it only where latency is visible (toggles, drag and drop), not for every form.

6. **Build the component and route.** Routes are file-based under `apps/web/src/routes/`; `routeTree.gen.ts` is regenerated by the TanStack Router Vite plugin, never hand-edited. No route in the app uses a `loader`; call the query hooks from components, as the trash route does. Render all four states, as `trash-list.tsx` does:
   - loading: `Skeleton` (`@/components/ui/skeleton`) or helpers in `@/components/ui/loading-skeleton`;
   - error: a message plus a retry calling `refetch`;
   - empty: `Empty`, `EmptyHeader`, `EmptyTitle`, `EmptyDescription` from `@/components/ui/empty`;
   - data.
   All copy goes through `t("namespace:key")`; follow the `i18n` skill. Gate actions on `useWorkspacePermission()` (`@/hooks/use-workspace-permission`) for display only; the API is the authority.

7. **Realtime.** If the mutation changes state other people see, the API side publishes an event (`publishEvent()` in `apps/api/src/events/index.ts`) and `apps/api/src/ws/index.ts` turns it into a project hint (`broadcastToProject`) or a user hint (`broadcastToUser`). On the web side:
   - project hints are handled in `apps/web/src/hooks/use-project-websocket.ts` (`onmessage`; add the type to a hint set or add an `if (message.type === ...)` branch that invalidates your key prefix);
   - user hints (notifications, favorites, drafts) in `apps/web/src/hooks/use-user-websocket.ts`.
   Hints carry ids, not data. The initiating tab is excluded from project broadcasts (`excludeInitiatorId`), so step 5 must refresh the author's own cache; the socket only updates other tabs and users. With Redis the same message goes through `redis-broadcast-adapter.ts`; nothing in the web app changes.

8. **Test.** Next to the file under test:
   - fetcher: mock `@margaya/libs` like `fetchers/label/delete-label.test.ts`;
   - mutation invalidation: mock `@tanstack/react-query` like `hooks/mutations/label/use-update-label.test.tsx`;
   - component states: mock the hooks and `react-i18next` like `components/trash/trash-views.test.tsx`.
   API behavior, authorization and the browser flow belong to the `testing` skill.

## Done when

- [ ] No raw `fetch` to the API; fetchers use `client` from `@margaya/libs` and throw `HttpError`.
- [ ] Every mutation refreshes what it makes stale (including the author's own tab), and the reverse action (delete/restore, assign/unassign) does too.
- [ ] Loading, empty and error states render, and every string is an i18n key.
- [ ] Realtime: another user's change shows up without reload (or it is a deliberate non-goal).
- [ ] Focused tests pass:
  `pnpm --filter @margaya/web exec vitest run --config vitest.config.ts src/path/to/file.test.tsx`
  (CI sets `NODE_OPTIONS=--no-experimental-webstorage` for jsdom storage; set it too if storage tests fail).
- [ ] Typecheck: `pnpm turbo typecheck --filter=@margaya/web` (builds the API and libs it depends on).
- [ ] `pnpm i18n:check` passes if you added copy.
