title: AI Privacy and Data
description: What Margaya's AI features may read, where each request goes, what is redacted, and what is never stored versus what is kept
---

This page collects how Margaya's AI features handle your data. For the settings themselves, see [AI Setup](/core/functional/ai-setup).

## Off until you turn it on

AI is off by default. Nothing is sent to any model until an instance admin allows AI and sets up a provider, and a workspace admin turns AI on for the workspace. Each project can stay out of AI entirely by turning **AI** off under its **Features**. See [AI Overview](/core/functional/ai-overview#what-has-to-be-turned-on).

## What AI may read

- **Only what the person can see.** Every AI feature reads through the same permission checks as the rest of Margaya. Agents are capped at both their role and the rights of the person they work for.
- **Projects with AI off** are never read, by any feature.
- **Restricted projects** stay out, even for their members, until a workspace admin turns on **Include restricted projects**.
- **Content is data, not instructions.** Task descriptions, comments, pages, search results and attachments are passed to the model inside marked blocks, and the model is told never to follow instructions found there.

## Where each request goes

Every request is classified by the most sensitive data in it:

| Tier | What it contains |
|---|---|
| **Restricted** | Content from a restricted project. |
| **Private** | Any other workspace content, such as tasks, comments and pages. Attached images always count as at least private. |
| **Public** | Only published content, or no workspace content at all. |

An instance admin decides where each tier may go: restricted data is **Never sent**, **Local model only** (the default) or **Cloud provider allowed**; other workspace data is **Local model only** or **Cloud provider allowed** (the default). **Local-only mode** on the instance, or **Local model only** in a workspace, sends every request to the local model. A workspace can be stricter than the server, never looser. A request whose only allowed destination is missing is refused rather than sent elsewhere.

Embeddings for semantic search and speech to text follow the same idea: an endpoint on your own network counts as local, any other as cloud, so a workspace that may only use local models never sends text or recordings to a cloud endpoint.

## Redaction

With **Redact personal data** on (for the server, or for one workspace), emails, phone numbers, card and IBAN numbers and credential-looking tokens are replaced with placeholders such as `[EMAIL_1]` before a request goes to a cloud provider. The same value always gets the same placeholder, and the answer shows the real values again, so people never see the placeholders. Requests to the local model are not redacted, and neither are attached images.

**Zero data retention** on the instance page only records that your agreement with the provider keeps no data; the provider enforces it.

## What is never stored

- **Prompts and answers.** By default Margaya doesn't keep what was sent to a model or what came back, for any feature. The exceptions are chat history that a workspace opts into, and agent run text when an instance admin turns on **Keep prompts and answers** (both below).
- **Reasoning.** A reasoning model's thinking text is shown only to the person who asked, and only when the instance shows reasoning. It is never stored or logged.
- **Attachments.** Files attached to an Ask question are used for that question only. Location and camera data are removed from PNG, JPEG and WebP images first.
- **Recordings.** With the server's speech-to-text endpoint, a dictated question is turned into text and only the text comes back; neither the recording nor the text is stored. Only **Local-only mode** (on the instance or a workspace) keeps recordings away from a speech service in the cloud; where private data goes chooses the AI model, not the speech service, so a local model and a cloud speech service can be combined. In voice mode, answers are read aloud by the voices built into your browser, so the spoken text never leaves your device. When the browser's own speech recognition is used instead, nothing reaches Margaya until you send the question. With **Capture**, a screen recording stays on your device: only a few still frames are sent.
- **Margaya's guides.** For questions about using Margaya, Ask searches the documentation that ships with your server. The guides are public text: searching them sends nothing anywhere, and links open the public documentation site.
- **Agent run input.** What you asked an agent is kept only while the run works, and dropped when it ends, unless the instance keeps prompts.

## What is kept

| Data | What it holds | Who sees it |
|---|---|---|
| **Usage ledger** | One row per model call: feature, person, agent and run, provider, model, data tier, outcome, tokens, cost and duration. No text. | People with **Manage AI** (their workspace); instance admins (totals across workspaces). |
| **Ratings** | A thumbs up or down, the optional reason, the feature and the model. Never the question or the answer. | People with **Manage AI**, next to usage. |
| **Chat history on the server** | Only when the workspace turns on **Keep chat history on the server**: each person's Ask conversations, up to 100 questions each, without reasoning. Otherwise history stays in each browser. | Only the person who had the conversation. Nobody else can open it, admins included. |
| **Memory notes and skills** | The text people saved under **AI memory** and **AI skills**. | See [AI skills and memory](/core/functional/ai-skills-and-memory). |
| **Agent runs** | The agent's summary (its answer, at most 2,000 characters, also used for follow-ups), its changes with values before and after, and its steps with shortened, redacted tool arguments. With **Keep prompts and answers** on, also the request text and the model's text of each step. | The person the run worked for; everyone with **Manage AI**. The request text: only the person the run worked for. |
| **Stakeholder briefs** | The computed facts each brief was written from, so the next brief can show what changed. The brief's text is kept only if you save it as a page. | Shown as **What changed since the last brief**. |
| **Translations** | One cached translation per text and language, so the next reader gets it without a new request. Replaced when the text changes, deleted with it. | Everyone who can see the text. |
| **Search index** | With semantic search on: vectors of tasks, pages and comments, without their text. Deleted with the item, or when semantic search is turned off. | Used only for search, with the usual permission checks. |
| **AI content labels** | On a task description, comment or page that AI wrote: how it was written (the feature or agent), the model when known, who accepted it or whom the agent worked for, when, and the last person who changed it since. No prompt or answer text. Deleted with the item. | Everyone who can see the item. See [AI transparency](/core/functional/ai-overview#ai-transparency). |

Anything you choose to save, such as a summary saved as a page or comment, an applied suggestion or a created task, becomes ordinary workspace content.

## Keep prompts and answers

**Keep prompts and answers** (instance setting `ai.retention.storePrompts`, or `MARGAYA_AI_STORE_PROMPTS`) is **off by default**. It decides whether AI request and answer text is kept after the work is done:

| | Off (default) | On |
|---|---|---|
| **Usage ledger** | Counts, cost, model and outcome. Never text. | The same: the ledger never holds text. |
| **Agent run request** | Kept while the run works or waits for your answer, then dropped. | Kept after the run ends, with your answers to its questions. Shown only to the person the run worked for. |
| **Agent run steps** | Tool names, outcomes, token counts and shortened, redacted arguments. | Also what the model wrote at each step (up to 8,000 characters). |
| **Agent run summary and changes** | Kept: the summary is the agent's answer, and the changes are needed to review and undo them. | Kept. |
| **Audit log** | Who did what, when, for whom. Never prompt text. | The same. |

Even with it on, Margaya never stores the context it assembles from your workspace (task text, comments, pages, search results): that is a copy of data that lives elsewhere and would outlive its deletion. Approvals keep a preview of the proposed change either way, because you need it to decide.

- **It applies going forward.** The setting is read when a run ends, or when the model answers a step. Turning it on doesn't recover text from earlier runs; turning it off stops keeping new text, and text kept meanwhile stays with its run.
- **Ask chat history is separate.** A workspace that turns on **Keep chat history on the server** keeps its people's Ask conversations whatever this setting says: that history is an explicit opt-in, and it is what lets people reopen recent conversations on another device. Turning this setting off neither turns that history off nor deletes it. Without the workspace opt-in, history stays in each browser.
- While it is on, workspace admins see **Prompts kept** next to where their data goes in the workspace's AI settings.

## Web search

When web search is on, only the person's question is sent to the search provider, never workspace content. Web results are cited as web sources and used for outside facts, never for the state of your work.

## Budgets and limits

- A **monthly budget** in US dollars for the whole workspace, and a **daily token limit** per person. From 80% of the budget, people with **Manage AI** get a notice; once a limit is reached, AI requests stop until the next month or day.
- A **monthly budget** per [agent](/core/functional/ai-agents).
- Requests per minute per workspace and per person, and requests at the same time per person, set by the server (see [Environment variables](/core/installation/environment-variables#ai)).

Costs are estimates by list price. Local models count as $0, but their tokens are still recorded.
