description: Use Margaya as an app on macOS, Windows and Linux, with native notifications you can act on, an unread badge, offline reading and sign-in through your browser

Margaya Desktop is a small app for macOS, Windows and Linux. It opens your Margaya server's own web app in its own window, so everything works exactly as it does in the browser and always matches your server's version. On top of that it adds what a browser tab can't:

- Native notifications, even when the window is closed, with **Mark done**, **Snooze 1 hour** and **Reply** buttons on task alerts.
- An unread count on the Dock icon, the taskbar button or, on Linux, the dock and the tray icon.
- **Quick add**, **Search** and **Today** from the tray, the menu bar or a keyboard shortcut, without opening a server's window. See [Quick add, search and Today](/core/functional/desktop-app-quick-add-and-search).
- Saved copies of the tasks and pages you opened recently, to read while a server can't be reached.
- Sign-in through your usual browser, so single sign-on works as it does there.
- Several servers side by side, each with its own sign-in.
- Updates that install themselves (on Linux, for the AppImage).

The app is a free download from the Margaya website. It isn't sold in any app store.

## Download and install

Go to [margaya.app/download](https://margaya.app/download). The page picks the right file for your computer and lists every other file, with its size and SHA-256 checksum. All files are also on the project's [GitHub releases page](https://github.com/manu14357/Margaya/releases).

### Linux requirements

- **A recent distribution.** Margaya uses WebKitGTK 4.1: Ubuntu 22.04, Debian 12, Fedora 38, openSUSE Leap 15.6 or later, a rolling distribution, or an RHEL-compatible release that provides WebKitGTK 4.1 (`webkit2gtk4.1`). The .deb and .rpm pull in what they need; the AppImage brings its own libraries.
- **A keyring.** Margaya keeps your sign-in in the system's secure storage through the Secret Service, so **GNOME Keyring** or **KWallet** must be running. GNOME, Ubuntu, KDE Plasma, Cinnamon and most other desktops start one at login. On a minimal window manager, start `gnome-keyring-daemon` (or KeePassXC with its Secret Service integration) in your session.
- **A tray.** Closing a window keeps Margaya in the tray. GNOME needs the [AppIndicator and KStatusNotifierItem Support](https://extensions.gnome.org/extension/615/appindicator-support/) extension for that; Ubuntu includes it. KDE Plasma, Cinnamon, XFCE and MATE show the icon as they are.

Margaya works on Wayland and X11.

## Add a server

The first time you open Margaya, it asks for a server.

1. Under **Add a server**, enter your server's address in **Server address**, for example `margaya.example.com`. The address you use in the browser works, and so does the API's address if your administrator gave you that one.
2. Click **Connect**. The app checks the server and shows **Found Margaya** with its version and address.
3. Change the **Name** if you like, then click **Add server**.

The server appears in the **Servers** list. Click **Open** to open it in its own window. To add another server, use **Add a server** again: each server keeps its own sign-in, cookies and window, so work and personal servers never mix. **Rename** and **Remove** are in the server's row.

<Screenshot src="desktop/server-list" alt="The Margaya window listing two servers: Studio North, signed in with 3 unread, and Personal, not signed in with a Sign in with browser button, each with Open, Rename and Remove; below them Add a server with the Server address field and Connect; Settings with switches for Open at login and Start minimized to the tray, Updates with the version, What's new and Check for updates, Update channel set to Stable, Pause notifications set to Off, a Keep recent items for offline reading switch, Saved copies with Clear saved copies, Spell-check language set to Same as the system, and Diagnostics with Copy diagnostics; and Keyboard shortcuts for Quick add, Search, Take screenshot to task and Today, each with Change, Clear and Reset" caption="The server list, with Add a server, the app's settings and its keyboard shortcuts below it." />
 Removing a server signs you out of it on this computer.

After the first time, Margaya opens straight into the server windows you had open when you last used it. The server list only appears when no server window was open. To get back to it, choose **Switch server…** from the tray or menu bar icon, or **Switch server** in the user menu of a server window.

A server on plain `http://` shows a warning and **Not secure (http)** in the list, except `localhost`. Only use one on a network you trust.

## Sign in

Click **Sign in with browser** next to the server. Your default browser opens the server's sign-in page:

1. Sign in the way you always do: password, email code, Google, GitHub, your company's single sign-on or SAML. If the browser is already signed in to that server, this step is skipped.
2. The browser shows **Sign in to the desktop app** with your account and the server's address. Check them and click **Allow**. If you didn't start this from the app on this computer, click **Cancel**.
3. The browser asks whether to open Margaya. Allow it.
4. The app shows **Signed in** and opens the server's window, already signed in.

<Screenshot src="desktop/browser-sign-in" alt="The Sign in to the desktop app page in the browser, asking to sign in to the Margaya desktop app as Elena Marsh on margaya.studionorth.example, with a warning to continue only if you started this from the app, and Allow and Cancel buttons" caption="The browser asks you to confirm before it hands the sign-in to the app." />

Signing in through the browser means your password manager, passkeys and your company's sign-in rules work as usual, and the app never sees your password.

A server's window that isn't signed in always opens on the server's sign-in page, never on the product landing page that signed-out visitors may see in a browser. There you can:

- Click **Sign in with your browser**, which starts the same browser sign-in as above and brings you back to the window, signed in.
- Sign in right in the window with a password or an email code. Single sign-on buttons there hand over to the browser too.

If the browser doesn't come back to the app, for example because a company policy blocks app links, choose **Show a code** in the app. The browser then shows a sign-in code instead: paste it into **Sign-in code** and click **Continue**. A code works once and expires after a minute.

The app keeps your sign-in in the system's secure storage (the macOS Keychain, the Windows Credential Manager, or on Linux GNOME Keyring or KWallet), never in a plain file. On Linux without a running keyring, signing in stops with **Couldn't save your sign-in in the system keychain**: see [Linux requirements](#linux-requirements). **Sign out** in the server's row signs this app out of that server and removes the stored sign-in. Signing out inside a server's window does the same: the app is signed out of that server too, and its notifications stop until you sign in again.

## Work in the app

A server's window looks like Margaya in the browser, without the browser around it:

- **Title bar.** On Windows and Linux, the minimize, maximize and close buttons sit at the right end of Margaya's own top bar (round buttons on Linux). Drag an empty part of the bar to move the window, and double-click it to maximize. On Linux, drag the window's edges to resize it. On macOS, the window buttons sit inside the top bar. A server that runs an older version of Margaya's web app shows the normal window frame instead.
- **Closing a window** hides it to the tray (Windows, Linux) or the menu bar (macOS), so notifications and quick add keep working. To quit, choose **Quit** from the tray or menu bar icon. On Linux, the tray icon opens its menu on any click; **Open Margaya** is at the top.
- **More windows.** <Kbd>Ctrl</Kbd>-click (<Kbd>⌘</Kbd>-click on macOS) a link, or choose to open it in a new tab, to open it in a second window of the app. **Open in new window** is in the menus of tasks, projects in the sidebar, pages and whiteboards; for pages and whiteboards it replaces **Open in new tab**. <Kbd>Shift</Kbd>-click or middle-click a task card, a task in a list or a project in the sidebar does the same. On a whiteboard, **Present in new window** opens the board in [present mode](/core/functional/whiteboards/canvas-and-navigation#present-a-board) in its own window, which you can move to a second screen.
- **Drop files.** Drag files from your computer onto a task's attachments, a task description, a comment, a page or a whiteboard to add them, as in the browser. Files dropped anywhere else are ignored, so a stray drop never replaces Margaya with the file.
- **Downloads.** Clicking an attachment opens the same [file preview](/core/functional/file-preview) as in the browser, inside the window; Ctrl-click and middle-click preview too, since the app has no tabs. The preview offers **Open in browser** only for files on other sites, because your system browser may not be signed in to your server. Files you download, with the preview's **Download** button, an attachment's download button, an export or a whiteboard image, go to your **Downloads** folder, under their own name; a file with the same name already there is kept, and the new one gets a number, such as `report (2).csv`. While files download, the taskbar button (Windows), the Dock icon (macOS) or the dock icon (Linux, in the docks that show the unread count) shows a progress bar; macOS shows that something is downloading, without the percentage. A notification tells you when each download has finished, or if it failed. Click it to show the file, selected, in File Explorer, Finder or your file manager; the file itself never opens. If you have deleted or moved the file since, or restarted Margaya, the click opens the folder instead, and a click on a failed download opens your **Downloads** folder. On Windows this also works from the notification centre after you quit Margaya: the click starts it in the tray and opens the folder.
- **Spell check.** The spell checker uses your system's language. On Windows and Linux you can pick another one under **Settings** > **Spell-check language**. Linux applies it right away. On Windows, servers whose window you already opened since Margaya started keep the old language until you restart Margaya. On macOS, the system's own spelling settings apply.
- **Other sites.** Links to other websites open in your browser. Linking your GitHub account, billing and installing the GitHub App continue in your browser. For linking, **Connect GitHub** opens the same settings page in your browser, where you connect GitHub; **Copy link** copies that page's address for a different browser. Margaya checks the link again when you come back to the app.
- **Keyboard.** <Kbd>Ctrl</Kbd> + <Kbd>,</Kbd> (<Kbd>⌘</Kbd> + <Kbd>,</Kbd> on macOS) opens Margaya's settings. On Windows, <Kbd>Ctrl</Kbd> + <Kbd>+</Kbd> and <Kbd>Ctrl</Kbd> + <Kbd>−</Kbd> zoom in and out. The browser's right-click menu and its back and forward shortcuts are switched off, so Margaya's own [keyboard shortcuts](/core/functional/keyboard-shortcuts) and menus work as expected.

### When the server is offline

If a server can't be reached, its window shows an offline screen instead of an error page. The app tries again on its own, after 2, 5, 10, 20 and 30 seconds and then every minute, and opens the server as soon as it answers. Click **Try again** to try right away, or **Switch server** to open another one.

<Screenshot src="desktop/offline" alt="The offline screen: Can't reach Studio North, the server's address, the last error, a countdown to the next try, Try again and Switch server buttons, and below them Recently opened with two saved tasks and a page, each with its workspace, project and when it was saved" caption="The window keeps trying on its own while the server is offline, and lists the saved copies you can read meanwhile." />

### Read saved copies offline

While you work, the app keeps a read-only copy of the last 50 tasks and pages you opened on each server. When the server can't be reached, the offline screen lists them under **Recently opened**, with when each was saved. Click one to read it: a banner says **You're offline — this is a saved copy from …**, and **Back to recently opened** returns to the list.

<Screenshot src="desktop/offline-saved-copy" alt="A saved copy of the task Redesign the pricing page, under an orange banner that says You're offline, this is a saved copy from the time it was saved, with Try again and Back to recently opened; below it the task's status, priority, due date and assignees, and its description with a Scope list and a checklist" caption="A saved copy is read-only plain text, with Try again always at hand." />

A copy is plain text: the title, the description or page text, and for a task its status, priority, due date and assignees. Images, attachments, comments and formatting aren't kept, and changes made since the copy was saved don't show. Each item keeps up to about 200 KB of text and each server about 4 MB in all. Only servers whose web app is recent enough to send copies get them.

<Info>
Saved copies stay on this computer only, in the server's folder of the app's data (under `profiles`, see [Uninstall](#uninstall)). They aren't encrypted, like a browser's cache, and never contain your sign-in. They are deleted when you sign out of the server, when you remove it, when you turn off **Keep recent items for offline reading** in **Settings**, or with **Clear saved copies** there, which deletes the copies of every server.
</Info>

## Notifications and the unread badge

Once you're signed in, the app shows Margaya notifications as native system notifications, with the same text you'd see in the browser. Clicking one brings Margaya to the front and opens the task or page in that server's window, without reloading it. On Windows this also works from the notification centre, and even after you quit Margaya: the click starts it and opens the page. On Linux, clicks work while Margaya is running; when you quit it, your desktop removes its notifications. On Wayland, some desktops announce **Margaya is ready** instead of bringing the window to the front: click that to switch to it. Notifications keep arriving while the window is closed, as long as Margaya is running in the tray or menu bar. A newer notification about the same thing replaces the older one, and when you use more than one server each notification names its server.

The Dock icon (macOS) or the taskbar button (Windows) shows how many unread notifications you have, added up across all your servers. Linux has no common badge: the count appears next to the tray icon, and on the dock icon in docks that support it (Ubuntu Dock, Dash to Dock, KDE Plasma's task manager and Plank). The **Servers** list and the tray menu show the count for each one.

While [quiet hours or focus mode](/core/functional/account-notifications#quiet-hours-and-focus-mode) hold the desktop app, new notifications only update the badge. When they end, one silent alert says how many arrived meanwhile. Focus mode started on any device, or from **Pause notifications** in the account menu inside the app, pauses the app's alerts too.

### Act on a task notification

Notifications about a task, such as an assignment, a status change, an update, a comment, a mention, a due-date reminder or an overdue task, can carry buttons:

| Button | What it does | When it appears |
| --- | --- | --- |
| **Mark done** | Moves the task to the first done column of its project and marks the notification read. | You can edit the task (Owner, Admin or Member by default), the task is still open, not archived and not waiting in intake, and its project has a done column. |
| **Snooze 1 hour** | Hides the notification from your inbox for an hour and marks it read. It comes back unread after the hour, and the app shows it again if it's still running. | Always, on task notifications. |
| **Reply** | Opens the task with the comment box ready for typing. | You can edit the task, which commenting needs. |

After **Mark done** or **Snooze 1 hour**, a short silent notification confirms it, or says it didn't work, for example because the task changed meanwhile: open the task in Margaya to try again. Margaya checks your permissions again when you press a button.

Where the buttons show depends on your system:

- **Windows** shows them under the notification text, also in the notification centre.
- **macOS** shows them under **Options** on the notification.
- **Linux** shows them where your desktop's notifications support buttons, as GNOME and KDE Plasma do.

Buttons work while Margaya keeps running. After Margaya restarts, a button on an older notification only brings Margaya to the front.

### Pause notifications

To stop the app's pop-ups and sounds for a while, choose **Pause notifications** in the tray or menu bar icon, or in **Settings**:

| In the tray | In **Settings** | Notifications come back |
| --- | --- | --- |
| **For 1 hour** | **For 1 hour** | after an hour |
| **Until tomorrow morning** | **Until tomorrow (8:00)** | at 8:00 on your computer's clock: tomorrow, or this morning if you pause between midnight and 8:00 |
| **Until I turn them back on** | **Until I turn them back on** | when you choose **Don't pause** in the tray or **Off** in **Settings** |

This pauses notifications from every server on this computer only, and keeps paused after a restart. The unread badge and the counts keep updating, and nothing is lost: everything is in your inbox. **Settings** shows until when notifications are paused. To pause on all your devices, use focus mode inside Margaya instead.

### Do Not Disturb and Focus

The app also stays quiet when your system says so:

- **Windows**: no pop-up and no sound while Do Not Disturb or Focus is on, during a presentation, or while an app or game runs full screen.
- **macOS**: Focus applies to Margaya's notifications as to any other app's.
- **Linux**: no pop-up and no sound while GNOME's **Do Not Disturb** is on. Other desktops' Do Not Disturb modes still hide the notification, but the app can't read them, so it may still play its sound; use **Mute sounds on this device** then.

The badge keeps counting in all these cases.

### Notification sound

Each new notification makes at most one sound, and a burst of notifications makes one. It follows your [notification sound settings](/core/functional/account-notifications#notification-sounds) in Margaya: it plays only when sounds are on, the volume isn't zero, a sound is chosen for that kind of notification and neither quiet hours nor focus mode is on (unless the notification is one you let through). **Mute sounds on this device**, set inside the app's window, silences the app's notifications on this computer.

<Screenshot src="desktop/notification-sounds" alt="The Sounds section of the notification settings inside the desktop app, explaining that the app plays the chosen Margaya sound at your volume, with Play sounds, Volume at 70%, a sound for each kind of notification and Mute sounds on this device" caption="Inside the app, the Sounds settings describe what the app plays." />

- **Windows**: the app plays the Margaya sound you chose for that kind of notification (Chime, Pop, Ding, Soft bell, Knock or Marimba) at your volume, instead of the Windows notification sound. It comes out louder than the preview in the settings: at volume 70 it is at least as loud as the Windows notification sound. It stays silent while notifications are paused or Windows holds them back (see [Do Not Disturb and Focus](#do-not-disturb-and-focus)), and when notifications for Margaya are turned off in Windows Settings. Windows' own **Play a sound** switch for Margaya doesn't apply to it; use **Mute sounds on this device** instead.
- **macOS**: the notification plays your system's notification sound. Focus and your per-app sound setting silence it as for any other app.
- **Linux**: the app plays the same Margaya sounds as on Windows, through your desktop's sound system (PipeWire or PulseAudio, using `paplay` or `pw-play`, or ALSA's `aplay`), at your desktop's alert volume. It stays silent while notifications are paused or GNOME's **Do Not Disturb** is on. Other desktops' Do Not Disturb modes still hide the notification, but the app can't read them; use **Mute sounds on this device** then.

A server older than this version doesn't name a sound; the app then plays Chime at volume 70.

Which events notify you is still set in Margaya, under [your notification settings](/core/functional/account-notifications). Inside the desktop app, browser push notifications are switched off, so you don't get everything twice: the **Push notifications** card is replaced by **Desktop notifications**, which explains that the app shows them on this computer. To silence the app completely, or change how its notifications look, use your system's notification settings.

## Quick add, search and Today

Without opening a server's window, you can:

- Create a task with **Quick add** (<Kbd>Ctrl</Kbd> + <Kbd>Shift</Kbd> + <Kbd>Space</Kbd>, or <Kbd>⌘</Kbd> + <Kbd>Shift</Kbd> + <Kbd>Space</Kbd> on macOS), with its due date, priority and assignees typed in the title, a description and attachments.
- Turn a screenshot, the clipboard or, on Windows, files from **Send to** into a task.
- **Search** every server and workspace at once (<Kbd>Ctrl</Kbd> + <Kbd>Shift</Kbd> + <Kbd>K</Kbd>, or <Kbd>⌘</Kbd> + <Kbd>Shift</Kbd> + <Kbd>K</Kbd> on macOS).
- Keep your overdue and due-today tasks in view in the **Today** window.

All of this is in the tray or menu bar icon too, and you can change the shortcuts. See [Quick add, search and Today](/core/functional/desktop-app-quick-add-and-search).

## Files window

The **Files** window browses folders on your computer and previews their files without opening another app. It's read-only: Margaya never changes, moves or deletes anything in it.

Open it from **Files** in the tray or menu bar icon, the **Files** button in the server list, or **Files** in the Windows taskbar jump list (and the Linux launcher's menu). You can give it a keyboard shortcut in [Settings](#settings); it has none by default.

### Add folders

Choose **Add folder…** and pick a folder. Margaya can read only the folders you add (with everything inside them) and the files you drop on the window. It can't read anything else on your computer, and server windows never get access to your files.

- Added folders are listed under **Places** and come back the next time you open the app.
- **Remove folder** (the **×** next to it, or its right-click menu) takes it off the list. Margaya can't read it again until you add it back. The folder itself is untouched.
- A folder that was moved, renamed or disconnected shows **Not available**. Remove it and add it again from its new place.
- Network shares and device paths can't be added.
- Shortcuts and links inside a folder open only when they point to somewhere inside a folder you added.

### Browse and find files

- Folders come first, then files, with their type, size and date modified. Sort by **Name**, **Date modified**, **Type** or **Size**, in either order, and switch between the list and the grid. The window remembers your choice.
- Type in the filter box to narrow the current folder by name. Turn on **Include subfolders** to search everything below it; **Stop** ends a long search.
- **Hidden items** shows files and folders your system hides.
- Click to select, double-click or press <Kbd>Enter</Kbd> to open a folder or preview a file. The arrow keys move the selection, <Kbd>Backspace</Kbd> goes up one folder, <Kbd>Ctrl</Kbd> + <Kbd>F</Kbd> (<Kbd>⌘</Kbd> + <Kbd>F</Kbd> on macOS) jumps to the filter, and <Kbd>F5</Kbd> refreshes. <Kbd>Delete</Kbd> does nothing here.
- Right-click a file, or press <Kbd>Shift</Kbd> + <Kbd>F10</Kbd>, for **Preview**, **Open with default app**, **Show in folder**, **Copy path**, **Save a copy…** and **Add to Recent** or **Remove from Recent**.
- **Recent** lists the last 20 files you previewed.

### Preview files

The preview opens beside the list. Drag its edge to make it wider, or expand it to fill the window. It shows PDFs, Word documents, spreadsheets and CSV files, presentations, images and SVGs, Markdown, text and code, web pages (without scripts or outside content), audio and video, ZIP archives and 3D models (STL, OBJ and glTF).

- **Save a copy…** saves the file wherever you choose. It's the only time the Files window writes anything, and only to the place you pick.
- **Open with default app** opens the file in the app your system uses for it. Programs and scripts (such as `.exe`, `.bat`, `.ps1` or `.sh` files) are never opened this way; use **Show in folder** instead.
- Drop files on the window to preview them, even from outside your folders. Drop a folder to add it to **Places**.

### Attach a file to a task

Drag a file from the Files window onto a task, a comment or a description in a server window, just as you would from your system's file manager. Margaya attaches it there.

## Open Margaya links in the app

Links that start with `margaya://open` open in the app, in the right server's window. If a link points at a server that isn't in your list, the app asks **Add this server?** first. Only add servers you trust; choose **Ignore** for anything you don't recognise.

## Updates

Margaya checks for updates on its own. When one is ready, the tray menu shows **Restart to update to** with the new version. You can also check yourself under **Settings** with **Check for updates**. Every update is signed, and the app refuses one that isn't.

On Linux, the AppImage updates itself the same way. A .deb or .rpm belongs to your package manager, so Margaya only tells you about the new version: **Download version …** in the tray, or **Download** in **Settings**, opens the download page. Install the new package over the old one with the same command you installed it with; your servers and sign-ins stay.

A server may need a newer app than yours. Then connecting shows **This server needs Margaya Desktop … or newer**: update the app and try again.

After an update, the next start opens the server list with **Updated to …** and that version's release notes, loaded from the project's GitHub releases. **Read the release notes** opens the full release page, and **What's new** in **Settings** shows them again.

### Update channel

**Settings** > **Update channel** picks which versions you get:

- **Stable**: the regular releases. This is the default.
- **Beta**: new versions before everyone else. They may have rough edges. On Beta, the app still offers a stable release when it is newer than the latest beta.

Beta versions are built only as the Windows setup (`.exe`), the macOS disk images and the AppImages; there is no beta MSI, .deb or .rpm.

## Settings

Open the settings with <Kbd>Ctrl</Kbd> + <Kbd>,</Kbd> (<Kbd>⌘</Kbd> + <Kbd>,</Kbd> on macOS), or **Settings…** in the tray or menu bar icon.

- **Open at login** is a switch that starts Margaya in the background when you sign in to your computer, so notifications and quick add are ready. On Linux it adds Margaya to `~/.config/autostart`.
- **Start minimized to the tray**: when Margaya opens at login, it waits in the tray without opening any windows. On by default; turn it off to have your server windows open at login. It only applies with **Open at login** on.
- **Updates** shows the version you have. **Check for updates** looks for a newer one; when there is one, **Restart to update** (or **Download** for a Linux .deb or .rpm) appears below it. **What's new** shows the release notes of your version. See [Updates](#updates).
- **Update channel**: **Stable** or **Beta**. See [Update channel](#update-channel).
- **Pause notifications**: **Off**, **For 1 hour**, **Until tomorrow (8:00)** or **Until I turn them back on**. See [Pause notifications](#pause-notifications).
- **Keep recent items for offline reading**, on by default, and **Saved copies** with **Clear saved copies**. See [Read saved copies offline](#read-saved-copies-offline).
- **Spell-check language** (Windows and Linux): **Same as the system**, or one of the languages Margaya is available in.
- **Diagnostics**: **Copy diagnostics** copies the app version, your system, your server list and recent log lines for a bug report. Sign-in tokens are never included. **Open logs folder** in the **Help** menu shows the log files.
- **Keyboard shortcuts** for **Quick add**, **Search**, **Take screenshot to task**, **Today** and **Files**. See [Keyboard shortcuts](/core/functional/desktop-app-quick-add-and-search#keyboard-shortcuts).

## Uninstall

<Tabs>
<Tab title="macOS">

Quit Margaya (**Quit** in the menu bar icon), then drag **Margaya** from **Applications** to the Trash. Your server list, window data and saved copies stay in `~/Library/Application Support/com.margaya.desktop`; delete that folder too if you want them gone. Sign out of each server first to remove its stored sign-in from the Keychain.

</Tab>
<Tab title="Windows">

Sign out of each server first, then open **Settings**, go to **Apps** > **Installed apps**, and choose **Uninstall** next to **Margaya**. To remove your server list and window data as well, delete `%APPDATA%\com.margaya.desktop` (the server list) and `%LOCALAPPDATA%\com.margaya.desktop` (each server's window data and saved copies, under `profiles`).

</Tab>
<Tab title="Linux">

Sign out of each server first, so its sign-in leaves your keyring, and quit Margaya. Then:

- **AppImage:** delete the file, and `~/.local/share/applications/margaya-desktop-handler.desktop` (its link handler).
- **.deb:** `sudo apt remove margaya`
- **.rpm:** `sudo dnf remove margaya`, or `sudo zypper remove margaya` on openSUSE.

To remove your server list and window data as well, delete `~/.config/com.margaya.desktop` (the server list), `~/.local/share/com.margaya.desktop` (each server's window data and saved copies, under `profiles`, and the logs) and `~/.cache/com.margaya.desktop`.

</Tab>
</Tabs>

## Private or company certificates

If the app says **Your computer doesn't trust this server's certificate**, the server uses a certificate from your company's own certificate authority, or a self-signed one. The app uses your system's list of trusted certificates and can't trust one server on its own.

Install the company's root certificate on your computer, then restart Margaya:

- **macOS:** open the certificate file in **Keychain Access**, add it to the **System** keychain, open it, and under **Trust** set **When using this certificate** to **Always Trust**.
- **Windows:** open the certificate file, click **Install Certificate**, choose **Local Machine**, and place it in **Trusted Root Certification Authorities**.
- **Linux:** add it to the system's certificate store. On Debian and Ubuntu, copy the certificate (PEM, ending in `.crt`) to `/usr/local/share/ca-certificates/` and run `sudo update-ca-certificates`. On Fedora and RHEL, copy it to `/etc/pki/ca-trust/source/anchors/` and run `sudo update-ca-trust`. On openSUSE, copy it to `/etc/pki/trust/anchors/` and run `sudo update-ca-certificates`.

On company computers your IT team usually installs this certificate for you, through device management or Group Policy. Never trust a certificate you don't know the origin of.

## Troubleshooting

<AccordionGroup>
<Accordion title="Couldn't reach this server">

Check the address and your network. Open the same address in your browser: if it doesn't load there either, the server is down or only reachable on a company network or VPN.

</Accordion>
<Accordion title="This address doesn't look like a Margaya server">

The address answered, but not like a Margaya server. Use the address you open Margaya with in your browser, or ask your administrator for the server's API address. If the server sits behind a sign-in portal, connect to the network or VPN that skips it.

</Accordion>
<Accordion title="This Margaya server doesn't support the desktop app yet">

The server runs a version from before the desktop app. Ask your administrator to update it.

</Accordion>
<Accordion title="Desktop sign-in is turned off on this server">

Your administrator has turned the desktop app off for this server. Keep using it in the browser.

</Accordion>
<Accordion title="The browser didn't come back to the app after sign-in">

On macOS, make sure Margaya runs from **Applications**, not from the disk image. Then use **Show a code** and paste the code into the app. If the code is refused, it has expired or was already used: start again, codes last one minute.

</Accordion>
<Accordion title="Your computer doesn't trust this server's certificate">

See [Private or company certificates](#private-or-company-certificates).

</Accordion>
<Accordion title="Windows blocks the installer">

Some company computers only allow signed installers. Ask your IT team to deploy the MSI for you, as described in [Desktop app for administrators](/core/installation/desktop-app).

</Accordion>
<Accordion title="Notifications don't appear">

Check that Margaya is running (its icon is in the tray or menu bar), that you're signed in to the server (signing out in the server's window also stops its notifications), and that **Pause notifications** in the tray is set to **Don't pause**. Check that notifications for Margaya are allowed in your system settings and that Do Not Disturb or Focus is off; on Windows, also leave full-screen apps and presentations. Then check which events notify you in [your notification settings](/core/functional/account-notifications).

</Accordion>
<Accordion title="A notification has no buttons">

Only notifications about a task get buttons, and only those that apply to you: see [Act on a task notification](#act-on-a-task-notification). On Linux, your desktop's notification service must support buttons. On macOS, look under **Options** on the notification. A server older than this version sends no buttons.

</Accordion>
<Accordion title="A server window shows the offline screen">

The app can't reach that server right now. It keeps trying on its own, so the window recovers once your network or VPN is back. If it stays offline, check the server in your browser, or use **Switch server** to work on another one. Meanwhile, you can read the tasks and pages you opened recently under **Recently opened**.

</Accordion>
<Accordion title="The window has the normal Windows frame">

That server runs an older version of Margaya's web app, which doesn't draw its own title bar yet. Everything else works; the title bar changes once your administrator updates the server.

</Accordion>
<Accordion title="A keyboard shortcut does nothing">

Another app is using the same combination, so Margaya couldn't claim it: **Settings** > **Keyboard shortcuts** then says **Not working right now: another app uses this combination.** Click **Change** to pick another one, or free it in the other app and restart Margaya. The action still works from the tray or menu bar icon. On Linux with Wayland, shortcuts only work while a Margaya window is in front.

</Accordion>
<Accordion title="Take screenshot to task comes back empty">

On macOS, allow Margaya under **System Settings** > **Privacy & Security** > **Screen Recording**, then try again. On Linux, install xdg-desktop-portal with a Screenshot backend for your desktop (GNOME and KDE Plasma include one).

</Accordion>
<Accordion title="I closed the window and Margaya is still running">

That's intended: closing a window hides it, so notifications and quick add keep working. Open it again from the tray or menu bar icon, or choose **Quit** there to stop Margaya.

</Accordion>
<Accordion title="Linux: there's no tray icon">

On GNOME, install and turn on the [AppIndicator and KStatusNotifierItem Support](https://extensions.gnome.org/extension/615/appindicator-support/) extension, then start Margaya again. Without a tray, open Margaya again from your applications or by running the AppImage: a second start brings back the window you used last.

</Accordion>
<Accordion title="Linux: Couldn't save your sign-in in the system keychain">

No keyring service answered. Check that GNOME Keyring or KWallet runs in your session (on KDE Plasma, KWallet's Secret Service must be turned on in **System Settings** > **KDE Wallet**), unlock it if it asks, then sign in again. Margaya never stores your sign-in in a plain file instead.

</Accordion>
<Accordion title="Linux: the window stays blank or white">

This happens with some graphics drivers, most often NVIDIA's on Wayland. Start Margaya once with `WEBKIT_DISABLE_DMABUF_RENDERER=1` set, for example `WEBKIT_DISABLE_DMABUF_RENDERER=1 ./Margaya_<version>_amd64.AppImage` or `WEBKIT_DISABLE_DMABUF_RENDERER=1 margaya-desktop`. If that helps, add the variable to the app's launcher or your session. If it doesn't, try X11 with `GDK_BACKEND=x11`.

</Accordion>
<Accordion title="Linux: the AppImage doesn't start">

Make sure the file is executable (`chmod +x`). On Ubuntu 22.04 and later, install `libfuse2` (`libfuse2t64` on 24.04), or run it with `--appimage-extract-and-run`. Start it from a terminal to see the error.

</Accordion>
<Accordion title="Linux: sign-in links don't come back to the app">

The .deb and .rpm register Margaya for its links when they install. An AppImage registers itself each time it starts, with `xdg-mime` from `xdg-utils`, which desktops include, so start it once after moving it. To check, run `xdg-mime query default x-scheme-handler/com.margaya.desktop`: it should name a Margaya `.desktop` file. Otherwise use **Show a code**.

</Accordion>
</AccordionGroup>

If none of this helps, choose **Copy diagnostics** and include it in an issue on [GitHub](https://github.com/manu14357/Margaya/issues).
