Margaya's AI features are optional and **off by default**. Each one proposes or explains; routine work never depends on AI, and everything still works when it is off. This page lists every AI feature and where to find it.

## What has to be turned on

AI features appear only when every level allows them:

1. **Instance.** An instance admin selects **Allow AI** and sets up a provider under **Settings** > **Instance** > **AI**.
2. **Workspace.** A workspace admin turns on **Turn on AI** under **Settings** > **Workspace** > **AI settings**.
3. **Project.** Each project keeps **AI** on, or turns it off under its **Features**. Off keeps the project out of AI entirely.
4. **Person.** People need the **Use AI** permission. Members, Admins and Owners have it by default; Viewers do not.

Some features need one more switch, listed in the tables below. See [AI Setup](/core/functional/ai-setup) for every setting, and [AI privacy and data](/core/functional/ai-privacy-and-data) for where data goes and what is kept.

## AI transparency

Margaya tells people when they are dealing with AI, as the EU AI Act's transparency rules (Article 50) ask. There is nothing to turn on.

- **Chat says it is AI.** The Ask AI panel says under its question box that you are chatting with an AI assistant, not a person, and that answers can be wrong. An agent's answer in your inbox carries an **AI-generated** label.
- **AI-written content is labelled.** A task description, comment or page that AI wrote shows a small **AI-generated** label. Hover it, or read it with a screen reader, to see how it was written: by which agent, or with which AI feature, and with which model when that is known.
- **What counts.** Text an agent writes, and text a person accepts from an AI feature: **Writing help** in descriptions, comments and pages (including **AI block**), **Write with AI** in **Create task**, summaries saved as a comment or page, spec drafts, Ask answers saved as a page, stakeholder briefs, retrospectives with an AI narrative, and the tasks that **Build with AI** and Build mode create. A page is labelled as a whole, because several people can edit it at once.
- **People's edits stay visible.** When a person changes AI-written text, the label reads **Edited by** and their name, **originally AI-generated**. When AI writes the text again, the label starts over.
- **Machines can read it too.** Tasks, comments and pages carry an `aiProvenance` field in API responses, MCP results, outgoing webhooks (task and comment payloads) and exports: null for text a person wrote, otherwise `source` (`assist` or `agent`), `feature`, `model`, `agentId`, `agentName`, `requestedById`, `generatedAt` and, after a person's change, `editedById`, `editedByName` and `editedAt`. CSV and Excel exports add an **AI generated** column.

Apps that write AI-generated text through the API label it by sending `aiAssist` with the feature name when they create or update a task, description, comment or page. Writes made by Margaya's own agents are labelled without it. Text a person writes, or text an outside tool sends without `aiAssist`, is not labelled.

## Usage and limits

Every AI request is counted by feature, person and model, with its tokens and cost. Workspace admins see it under **Settings** > **Workspace** > **AI settings** > **Usage** and can set a monthly budget and a daily token limit per person. See [AI Setup](/core/functional/ai-setup#usage-and-costs).
