---
title: Outgoing webhooks
description: Send task activity from a Margaya project to Slack, Discord, Telegram, or any HTTP endpoint. Configure per-project notifications and optional signing.
---

Margaya can notify external systems when tasks change in a project. Each integration is per project and uses either an incoming webhook URL from the service you connect (Slack, Discord, Mattermost), a bot token plus chat ID (Telegram), or your own HTTP listener (generic webhook).

<Info>
These integrations are outgoing only: Margaya posts to your URL when events occur. They are separate from [GitHub integration](/core/integrations/github/setup), which syncs issues and repositories. To receive events from a whole workspace instead of one project, use [workspace webhooks](/core/functional/webhooks).
</Info>

## Where to configure

1. Select **Settings** at the bottom of the left rail, then **Projects**.
2. Pick the project in the project switcher and open **Project integrations**.
3. Expand the integration you want under **Chat and webhooks**.

<Screenshot src="integrations/overview" alt="The Project integrations page with GitHub and Gitea under Code hosting, and Discord, Generic webhooks, Slack, Mattermost and Telegram under Chat and webhooks" caption="Every integration is set up per project from Project integrations." />

## Task links in notifications

Notification messages and generic webhook payloads include links to the task in the web app. Set [`MARGAYA_CLIENT_URL`](/core/installation/environment-variables) to your public Margaya web URL so those links point to your instance (for example `https://margaya.example.com`).

## Events you can subscribe to

Slack, Discord, Mattermost, Telegram and generic webhooks share these toggles under **Event notifications**:

| Toggle | Default | Description |
| --- | --- | --- |
| **New tasks** | On | New task in the project |
| **Status changes** | On | Status column changed |
| **Priority changes** | Off | Priority changed |
| **Title changes** | Off | Title edited |
| **Description changes** | Off | Description edited |
| **New comments** | On | New comment on a task |

Generic webhooks have six more, all off by default: **Task deleted**, **Task moved**, **Due date changed**, **Assignee added**, **Assignee removed** and **Due-date reminders**.

Defaults apply when you first connect; you can change toggles anytime in project settings.

## Slack

Use a [Slack incoming webhook](https://api.slack.com/messaging/webhooks) URL. It must match Slack's format:

`https://hooks.slack.com/services/T00000000/B00000000/XXXXXXXXXXXXXXXXXXXXXXXX`

Paste the URL in the Slack section, optionally set a channel label for your own reference, choose events, and save.

Margaya sends formatted messages to Slack when enabled events occur.

## Discord

Create an incoming webhook for a Discord channel (Channel settings → Integrations → Webhooks). The URL must look like:

`https://discord.com/api/webhooks/000000000000000000/xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`

(or the `discordapp.com` hostname). Paste it into the Discord section, optionally add a channel name label, select events, and save.

## Telegram

Create a Telegram bot with [`@BotFather`](https://t.me/BotFather), then add that bot to the destination chat, group, channel, or topic. Telegram requires:

- A bot token
- A chat ID
- Optionally a topic thread ID for forum-style group topics

To find the chat ID, send a message in the destination and open:

`https://api.telegram.org/bot<YOUR_BOT_TOKEN>/getUpdates`

Look for `message.chat.id` or `channel_post.chat.id`. If you are posting into a forum topic, also copy `message.message_thread_id`.

Paste those values into the Telegram section, optionally add a chat label, choose events, and save.

## Generic HTTP webhook

Use a generic webhook when you want a JSON POST to your own service, automation, or middleware. Expand **Generic webhooks**, enter the **Endpoint URL**, optionally a **Signing secret**, choose the events and select **Connect webhook**.

### Delivery health

After delivery attempts, Margaya stores basic health metadata (for example last success, last failure message, failure count) so you can see whether recent posts succeeded. This does not replace monitoring on your endpoint.

### Payload shape

Each POST has `Content-Type: application/json`. Top-level fields:

- `event`: string, one of: `task.created`, `task.status_changed`, `task.priority_changed`, `task.title_changed`, `task.description_changed`, `task.comment_created`, `task.deleted`, `task.moved`, `task.due_date_changed`, `task.assignee_changed`, `task.unassigned`, `task.due_date_reminder`
- `timestamp`: ISO 8601 time when Margaya sent the request
- `integration`: `{ "type": "generic-webhook" }`
- `project`: `id`, `name`, `workspaceId`
- `task`: `id`, `number`, `title`, `status`, `priority`, `url` (link to the task in the web UI)
- `actor`: `id` and `name` of the user when available, or nulls for automated actions
- `data`: event-specific fields (for example `oldStatus` / `newStatus` for status changes, `comment` text for comments)

Use these payloads to drive custom workflows, internal dashboards, or bridges to other tools.

### Signature verification

If you configure a secret for the generic webhook integration, Margaya signs each request and sends the result in the `X-Margaya-Signature` header.

- Header: `X-Margaya-Signature`
- Algorithm: `HMAC-SHA256`
- Signed input: the exact raw request body Margaya sends
- Encoding: lowercase hex digest

To verify a request:

1. Read the raw request body before parsing or re-serializing JSON.
2. Compute an `HMAC-SHA256` using your integration secret and that raw body.
3. Compare your computed lowercase hex digest with `X-Margaya-Signature` using a constant-time comparison.
4. Reject the request if the signatures do not match.

Margaya currently signs only the raw request body. It does not include a separate timestamp value in the signature input or send a dedicated timestamp header for replay protection. If you add replay defenses in front of your receiver, document that behavior separately so it does not drift from Margaya's payload contract.
